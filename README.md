# Nodes

> ⚠️ **改代码前先读 [AGENTS.md](./AGENTS.md)。** 那是本仓库的规则文件，
> 记着几条硬性禁令（最容易违反的一条：**不要用 shell 改含中文的文件**，
> 已经因此损坏过 3 个文件）。

本地优先的知识库笔记软件，内置可自定义模型的 AI 对话。
**核心工程目标：把大模型 prompt 前缀缓存命中率做到尽可能高。**

类语雀的文档树与 Markdown 编辑，但每一个段落都是可被 `@` 引用的独立
「知识块」。挂载进对话的块会稳定地进入上下文前缀，在后续每一轮里以约
**1/10 的价格**被复用 —— 而且这件事在界面上是**看得见**的：每一轮都实时
展示分层构成、命中预测、失效根因与实际省下的钱。

---

## 30 秒理解它的核心

普通笔记软件接 AI 是这样的：

```
[每次重新拼一整段 prompt] → 全价计费
```

Nodes 是这样的：

```
第一轮                         第二轮
┌─ L0 人设 ─────────┐         ┌─ L0 人设 ─────────┐ ← 逐字节相同，命中
├─ L1 工作区约定 ────┤         ├─ L1 工作区约定 ────┤ ← 命中
├─ L2 知识块清单 ────┤   →     ├─ L2 知识块清单 ────┤ ← 命中
├─ L2 知识块正文 ────┤         ├─ L2 知识块正文 ────┤ ← 命中
├─ L3 对话历史 ──────┤         ├─ L3 对话历史 ──────┤ ← 命中（只追加）
└─ L4 本轮输入 ──────┘         └─ L4 本轮输入 ──────┘ ← 只有这一层是全价
                                    命中率 90%+，输入成本降到约 1/5
```

实现这件事靠的不是某个技巧，而是一整套**确定性**约束（见下文与
[DESIGN.md](./DESIGN.md)）。

## 快速开始

```bash
# 1. 安装依赖（项目内已配好 .npmrc，npm 缓存落在工作区内）
npm install

# 2. 启动
npm run dev
# 打开 http://localhost:3210
```

首次启动会自动在 `.data/nodes.db` 建库，并预置 4 个**待填 API Key** 的模型
配置（DeepSeek / Kimi / Claude / OpenAI）。

**第一步：填一个 Key。** 点左上角齿轮 → 「模型配置」→ 编辑任一模型，
填入 API Key。没有 Key 时界面其余功能都能正常用，只有真正发起对话会报错。

**第二步：写点东西。** 左侧「文档」旁的 `+` 新建文档，直接写 Markdown。
保存后右侧预览里的每一段都会显示块标识，右上角有个「引用」按钮。

**第三步：问它。** 点标题栏的「对话」新建会话，在输入框里输入 `@`
唤起知识块选择器，挂载几段，然后提问。右侧的「缓存构成」面板会实时告诉你
这一轮会命中多少。

### 换一台机器继续（clone 之后注意什么）

仓库里**只有代码**。下面三样东西被 `.gitignore` 排除，`git clone` 之后是没有的：

| 不在仓库里的 | 为什么 | 换机器怎么办 |
| --- | --- | --- |
| `node_modules/` | 几百 MB、几万个文件 | 先跑 `npm install`（项目内 `.npmrc` 把缓存重定向到工作区，不会污染全局） |
| `.data/` | **你的笔记**（SQLite + 上传的图片） | 想要笔记就**手动复制整个 `.data/` 目录**过去；不复制就是一份全新的空库 |
| API Key | 只存在 `.data/nodes.db` 里，从不进代码 | 在新机器上重新进「模型配置」填一次 |

> **笔记不会跟着代码走。** `.data/` 被刻意排除，所以它既不会因为
> `git push` 泄露到公开仓库，也不会因为你换了台机器就自动出现 ——
> 这两件事是同一个设计的两面。跨机器同步笔记请用 U 盘 / 网盘直接复制
> `.data/`，复制前先关掉服务。

## AI 能对你的笔记做什么

它不只是"回答问题的聊天框"，而是**能动手整理**的助手：读文档、建文档、
改写正文、改名、移动分类、把没用的放进回收站。

这条边界改过一次。最初的设定是"AI 只能追加，不能删改移动"，
理由是保护数据。但那个理由**已经不成立了** —— 删除现在是软删（可恢复），
改写走追加式修订（旧版本都在库里），加上快照撤销，每个动作都可逆。
而"只能追加"的代价一直存在：**这样的助手当不了导师**，
它没法说"这两篇该合并""这块放错分类了""这段理解是错的"，
只能往你已有内容的后面贴补丁。

判据因此从"不做危险动作"换成了"**每个动作都可撤销**"。

### 它能做的

| 动作 | 说明 |
| --- | --- |
| 读 | 列出全部文档、读任意一篇的正文、按关键词搜知识块 |
| 新建 | 新建文档或模块，可直接写入正文 |
| 追加 | 往已有文档末尾追加内容，既有内容一字不动 |
| **改写** | 重写整篇正文：合并重复、纠正错误、重组结构、加小标题 |
| **改名 / 移动** | 把文档移进合适的模块，或把标题改准确 |
| **删除** | 放进回收站（可恢复） |

### 它不能做的（四条底线）

1. **改写不得让既有内容消失。** 每一个原有知识块的文字必须原样出现在新
   内容里，否则整次调用被拒绝、文档一个字都不动。要删就得显式删，
   不能作为改写的副作用发生。
   - ✅ 允许重排、合并、拆分、插入新内容
   - ❌ 拒绝任何既有文字消失
2. **含子文档的模块不许删。** 影响面太大（一次带走十几篇），
   要求它先逐篇处理 —— 把一次大误操作拆成若干次可核对的小操作。
3. **不能移动进自己的子树。** 那会让整棵子树从文档树上消失。
4. **不能改人设与工作区约定。** 那是每轮固定前缀，要改由你来改。

### 撤销的两个注意点

- **撤销 = 回到 AI 动手前那一篇的样子。** 所以如果你在 AI 写入之后
  **自己又改了**这篇文档，点撤销会**一并丢掉你的改动**。这是"整篇快照"
  方案的固有代价，界面上会写明。
- **撤销本身也能撤销。** 新建类的撤销是"放进回收站"而不是彻底清除，
  一次误点不会永久少一篇。

完整策略（含每条底线的理由与验证方式）见
[docs/agent-write-policy.md](./docs/agent-write-policy.md)。

## 面向学习的用法

这个软件是按"准备游戏开发求职"这类**系统性学习**场景设计的：

```
Unity                 ← 模块容器（不写正文，只挂载知识点）
├── 生命周期           ← 知识点文档
├── 性能优化
│   └── ```diagram     ← 排查路径图，节点可点回其他文档
└── C# 底层
图形学                 ← 另一个模块
```

1. **先立模块，再填知识点。** 模块是"这个方向"的容器，它本身就是知识结构的
   一部分。已经写成普通文档的，点标题栏那个转换图标即可变成模块（内容不丢）。
2. **用图串起知识点。** 流程图里的 `--> doc:<文档id>` 会变成可点击节点，
   于是"排查路径"这类内容能直接跳到对应知识点。
3. **交给 AI 分析。** 打开模块 → 点「AI 分析」，AI 会看到这个模块下
   **全部**知识点（含子模块，会摊平），以**秋招面试官**的视角评估：
   先挑出站不住的内容（错误、含糊、撑不住追问的地方），
   再说明这块**会被怎么考**（真实问法、答到什么程度算过关、哪些回答一听就是背的），
   最后给**带时间账**的取舍建议 —— 包括"这块可以了，别再投入"。
4. **面某个岗位之前，用「岗前准备」。** 把岗位 JD 粘进去，它会告诉你：
   这个岗位实际在找什么人（以及 JD 没写但能推断的）、你的内容与它的匹配度、
   今天就能开始做的准备清单（含**项目经历该怎么讲** —— 从企业软件转游戏，
   这段怎么包装、以及**不要硬吹**的边界），以及面试时**该反问什么**。
   最后会单独说一句"这场面试你最可能挂在哪里"。

缓存仪表在这里是**加分项**：它让你看到"整个模块挂进去之后，后续每轮复用
这些内容只要约 1/10 的价格"，而不是需要刻意优化的目标。

### 图片

三种入口，都会把图片插到光标处（前后自动补空行，自成一段）：

- **粘贴**：截图工具（微信 / QQ / `Win+Shift+S`）截完直接 `Ctrl+V`
- **拖入**：从资源管理器把图片文件拖到编辑区
- **按钮**：工具栏第一个图标，可一次选多张

图片以**内容哈希**为文件名存在 `.data/assets/` 下，正文里只写
`![说明](asset:<sha256>.png)`：

- 同一张图重复粘贴得到**同一个引用**，不会产生副本，也**不会让缓存前缀失效**
  （块的 `cacheKey` 只取决于正文文本，正文没变前缀就没变）。
- 正文里存的是内容指纹而不是句柄，所以删除再传同一张图，引用依然对得上。
- 点击图片会在新标签页打开原图（自带"查看大图"，不依赖脚本）。
- 只接受 PNG / JPEG / GIF / WebP，按**文件头魔数**判定 —— 改扩展名伪装成图片的
  HTML 会被拒绝。
- 删除正文里的引用**不会**自动删除文件：宁可留下孤儿素材，也不冒"误删还在用的图"的
  风险。`extractAssetIds()` 可用于统计孤儿。

### 表格

标准 Markdown 表格语法，渲染器支持列对齐，宽度超出时会横向滚动而不会撑破布局：

```markdown
| 状态 | 触发条件 | 处理 |
| --- | :--: | ---: |
| 硬直 | 受击后 12 帧内 | 不可操作 |
| 浮空 | 击飞值 > 阈值 | 可追击 |
```

表格是**一个知识块**，所以整张表可以被 `@` 引用，也可以单独交给 AI 评判。

### 大纲

大纲把文档里的 `#` 标题抽成树，点一下跳到对应位置。三件事针对"小节特别细碎"
的情况做了处理：

- **自动宽度**：按标题实际长度估算一个够用的初始宽度（最长能到 340px），
  不再把标题用省略号切掉 —— 你给小节起名就是为了概括内容。宽度仍可拖拽。
- **折叠**：每个有子标题的项前面有箭头，收起后整棵子树隐藏，并显示
  "里面还藏着几条"。标题行右侧的按钮可以**一键只留顶层**，在"看骨架"和
  "看细节"之间切换 —— 这是"细粒度大纲食之无味"的直接对策。
- **搜索强制展开**：折叠与搜索会互相打架（折起来的节点里搜到东西却看不见），
  所以搜索期间一律忽略折叠状态。

### 人设

人设是**工作区级**的：所有对话共用一份，新建对话没有自己的人设字段 ——
改一次就全部生效。

默认人设是**秋招期的游戏行业指导导师**，它知道自己面对的是一个
"**正在**秋招、不是准备秋招"的人。这一点决定了它怎么给建议：

- **时间账是硬约束**：任何建议都要说明占多少时间、以及它挤掉了什么。
  没有时间账的建议，对时间被面试切碎的人等于帮倒忙。
- **替我排优先级，而不是给平铺清单**：直接说"现在就做这个""这个放掉"。
  排优先级正是来找它的原因。
- **敢说"这块可以了，别再投入"**：只给"还缺什么"的评估会让人永远停不下来。
- **把"能力问题"和"匹配问题"分开**：秋招会连续受挫，而很多挂着其实是
  方向不对、职级不符、HC 冻结 —— 补技术根本没用。把它一律归因成
  "我学得不够"会让人陷入无限补漏。
- **面试实战视角**：不只判断知识对错，还告诉你这件事会被怎么问、
  答到什么算过关、哪些回答一听就是背的、该主动往哪引、该避开什么。
- **懂招人方为什么招这个岗位**（新项目立项 / 老项目救火 / 出海 / 技术栈迁移），
  因为那决定了他想听什么答案。

另外三条一直保留的取向：多视角（技术 / 场景 / 商业市场 / 玩家体验 / 工程现实）、
场景先行（禁止"视情况而定"式敷衍）、诚实边界（**编造比说"不知道"的危害大得多** ——
你会把它当知识背下来，然后在面试里被拆穿）。

默认文本在 `src/lib/db/defaults.ts`，设置里可以改，「恢复默认」一键还原。

> ⚠️ **播种只对空库生效。** 已有的库不会因为升级而自动换人设 ——
> 那等于覆盖你编辑过的内容。要换成新版默认值，走设置里的「恢复默认」，
> 或者直接改库（`repo.updateWorkspace`）。
> 代价是 L0 变化会让所有会话的整段缓存重建一次；这是刻意的取舍：
> 人设写得不合适就该改，不该为了命中率把系统提示冻结在一个不称职的版本上。

**这里修过两个会让功能失效的缺陷，都值得记下来。**

**其一：输出契约否决了「查漏补缺」。** 原契约写的是：

> 只依据提供的知识块内容作答；知识块里没有的信息，明确说明"知识块中未涵盖"。

而「AI 分析」要的正是"这个模块还缺什么"——**"缺什么"必然在知识块之外**。
按原契约，模型只能回答"知识块中未涵盖"，于是这个功能被自己的提示词否决了：
你看到的会是"分析完了但什么都没说"。

现在划界改成**区分事实与判断**：

| | 规则 |
| --- | --- |
| 事实 | 不许编造。不确定就说不确定，并指出该去哪里验证 |
| 判断（缺口、错误、过时、易错点） | 本来就是模型的职责，该给就说 |
| 来源 | 必须分清哪些是笔记原文、哪些是模型的判断 |

另外 L0 开头原先固定拼一句「你是「XX」这个知识库的写作与分析助手」，
和人设里的「面试陪练」直接打架；而且模板句更靠前、更像系统指令，
会稀释你写的定位。现在人设非空时**一句角色话都不加**。

回归测试：`tests/persona.test.ts`（11 项，两条缺陷都有守卫）。

### 图表语法
````markdown
```diagram
# 掉帧排查路径
掉帧 --> 合批
掉帧 --> 过绘制
合批 --> doc:doc_abc123        // 点击跳到这篇文档
过绘制{要不要看 GPU} --> 抓帧
合批 --> url:https://example.com
```
````

`#` 开头是标题，`-->` 有向、`---` 无向，`A["显示名"]` 命名，
`A{判断}` 画成菱形，`-->|标注|` 加连线说明，`//` 开头是注释。
写错的行不会让整张图作废，会在图下方列出可读的警告。

## 缓存命中是怎么做到的

这一节是整个项目的核心。所有约束都写在
[`src/lib/cache/assemble.ts`](./src/lib/cache/assemble.ts) 与
[`src/lib/cache/layers.ts`](./src/lib/cache/layers.ts) 里，改动前请先读
[DESIGN.md](./DESIGN.md) 第 2 节。

### 1. 上下文按稳定性严格分层

任何低稳定层的内容都不允许出现在高稳定层之前。L0 → L4 的顺序是硬约束，
有测试守着。

### 2. 知识块按内容哈希排序，与 `@` 的先后无关

同一组块无论用户怎么点选，渲染出的文本**逐字节相同**。用码点比较而非
`localeCompare`，避免 ICU 版本导致排序漂移。

### 3. 绝不把易变内容放进 prompt

时间戳、随机 ID、"当前第 N 轮"一律下推到 L4。有测试专门断言 prompt 里
不出现 ISO 时间戳和 UUID 形态的字符串。

### 4. 块身份在编辑与插入时保持稳定

这是最容易出错、也是代价最大的一环。块的 `cacheKey` 由内容哈希与 id 共同
决定，而"保存文档"时会重新解析整篇 Markdown，所以**块身份的认领**必须足够
聪明 —— 否则用户在第 3 段插一段，第 4 段起的每一块都会被当成新块，
引用这篇文档的所有会话缓存被整体击穿。

实现走三趟（顺序不可变）：

1. **按内容哈希**把所有没变动的块钉回原 id —— 扛住"在中间插入/删除"。
2. 用**位置提示**消化剩下的槽位，也就是内容被改过的块 —— 扛住"编辑一段"。
3. 都没匹配上的才是真正的新块。

### 5. 只有已被证明稳定的层才打断点（Anthropic）

写入缓存要付 1.25x，读取只要 0.1x。给一个每轮都变的层打断点是**净亏损**。
所以只在"与上一轮逐字节相同"的最深一层打断点；全都在变时就完全不打。
前缀短于服务商最小可缓存长度（约 1024 token）时也不打。

### 6. 缓存代价随时可见

- 编辑块前会提示"这段被 N 个会话引用，改了会让它们的 L2 缓存重建"。
- 切换模型会提示"服务商缓存不互通，本轮需重建"。
- 改人设 / 工作区约定会明确列出会失效的层。
- 每轮结束展示"实际 / 不缓存需要花多少 / 省下多少"。

## 排错

### 点了 AI 按钮，思考半天最后什么都没返回

最典型的原因是**推理模型的思维链与正文共用 `max_tokens`**。思维链把输出预算
烧完，正文一个字都还没开始写就被截断了 —— 流本身完全正常，所以看起来像
"想完了就没结果"。

查 `.data/nodes.db` 里那个模型的 `max_tokens`：

```powershell
node -e "const D=require('better-sqlite3');const d=new D('.data/nodes.db');console.table(d.prepare('SELECT name,model,max_tokens FROM model_config').all())"
```

**解法是留空，不是填大一点。** 到「模型配置」里把「最大输出」清空 ——
留空 = 不限制：请求里**根本不带** `max_tokens`，由服务商按它自己的上限约束
（DeepSeek 思考模式的原生默认是 64K）。

> **为什么"调大"治不好**：这个问题复发过两次。4096 烧完过一次，提到 8192
> 之后**又烧完了一次** —— 因为病根不是数字大小，而是"填了一个具体数字"。
> 只要还填着数，思维链够长就还能把它烧完。所以默认值现在就是"不限制"，
> 旧库里停留在 `4096` 或 `8192`（两代旧默认值）的配置会在下次启动时
> 自动改成"不限制"；**你手动调成 2048 或 16384 的都会原样保留**。

> **Anthropic 是唯一做不到的**：Messages API 把 `max_tokens` 定成必填，
> 省略会直接 400。所以在 Anthropic 上"留空"会被兜成 64000 发出，
> 并且每轮都会提示一句这不是真的无上限。

从 v0.2 起，这种情况会明确告诉你原因和该改哪个值，而不是只说
"可能是输出被 max_tokens 截断"。四种"没有正文"的情形会被分开归因：

| 形态 | 提示 |
| --- | --- |
| 思考烧完预算 | 给出当前上限、建议值，并说明已产生的思考仍可展开查看 |
| 纯截断 | 直接指向「最大输出」 |
| 只想不写（正常结束） | 提示换问法，不误导你去调参数 |
| 真空响应 | 报出服务商的停止原因 |

> **为什么改默认值要动你已有的库**：只改种子默认值对老库没用 ——
> 配置早就在库里了。所以迁移会补一次，判据是 `max_tokens` 等于某代旧默认值
> （`4096` 或 `8192`）。这个迁移要做表重建（旧库里这一列是 `NOT NULL`，
> 写不进 `NULL`），重建过程全程不动原表名，否则 `conversation` 的外键会被
> SQLite 顺手改写成指向临时表、表一删就悬空。

回归测试：`tests/integration/empty-reply.test.ts` 用本地 mock 服务端造出这四种
形态，跑真实的 `runChatTurn` 断言每一种的归因。它还守住一个容易被忽略的 bug：
**空回复必须记成失败轮次**，否则它会被当成下一轮的缓存基准，而它根本没往
服务商缓存里写过任何东西。

### 界面疯狂闪烁 / 终端被同一个请求刷屏
这是**渲染循环**的典型症状：父组件把内联箭头函数当回调传给子组件，而子组件
又把它放进了 `useEffect` / `useCallback` 的依赖数组，于是
"effect → 回调 → 父组件 setState → 重渲染 → 新回调引用 → effect" 无限循环。
症状很像后端问题，其实是纯前端问题。

**排查方式**：控制台里搜 `[nodes]`。关键组件上挂了 `useRenderWatchdog`，
判定为循环时会直接点名报错。控制台里还可以执行

```js
copy(window.__nodesRenderProbe())   // 每个组件的渲染次数与中位间隔
```

**先看 `中位间隔ms` 这一列**，它才是判断真假的依据：

| 中位间隔 | 含义 |
| --- | --- |
| **< 4ms** | 真循环 —— JS 线程被占满，没有机会回到事件循环 |
| 10ms 以上 | 正常。AI 流式回答每来一个 token 就渲染一次，30 次/400ms 是健康节奏 |

> 早期的看门狗只看"1 秒内是否超过 30 次"，于是**每次 AI 流式回答都会误报**。
> 已改为"次数够多 **且** 中位间隔 < 4ms"两个条件同时成立。这是
> AGENTS.md R4.2 记录的那一轮弯路。

**注意组件栈里的名字**：React 19 给的组件栈是 **owner**（谁创建了这个元素），
不是"哪个组件抛的"。所以看到 `at WorkspaceShell (...:705)` 时，
真正报警的可能是它渲染的 `<ChatPanel>` —— 以消息里打印的 label 为准。

**修复方式**：回调用 `useStableCallback`（`src/lib/ui/hooks.ts`）包一层，
父组件侧的回调统一 `useCallback`。详见 [DESIGN.md](./DESIGN.md) 第 5 节。

回归测试有两处：
- `tests/ui/render-loop.test.tsx` —— 刻意用内联箭头函数当 props，
  把 `useStableCallback` 去掉就会立刻变红。
- `tests/ui/watchdog.test.tsx` —— 判据本身：注入可控时钟构造出
  "真循环"（必须报）与"流式输出"（必须静默）两种场景。
  没有它的话，"看门狗因为自身 bug 而永不报警"和"判断为正常"输出完全一样。

### 终端里打印一堆 `✓ Compiled in xxms`

这不是错误，是 Next 的 Fast Refresh 在你每次保存文件时重新编译。
只有当它伴随浏览器控制台报错时才需要关注。真正的服务端错误会以
`"level":"ERROR"` 记录在 `.next/dev/logs/next-development.log`，可以直接查：

```powershell
Select-String -Path .next\dev\logs\next-development.log -Pattern '"level":"ERROR"'
```

### 改完代码后数据库多了/少了列

数据库迁移在 `src/lib/db/index.ts`，由 `getDb()` **每次**保证已应用
（不是只在第一次建连接时跑）。这一点是有意的，见该文件里那段长注释 ——
曾经因为"迁移只在建连接时跑"，热重载后新迁移一次都没生效，
表现是"功能一保存就 500 / no such column"。回归测试在
`tests/integration/migration.test.ts`。

### 数据库

数据在根目录的 `.data/nodes.db`（单文件 SQLite）。删掉整个 `.data` 目录
即可重置到全新状态 —— **但请先停掉 dev server**，否则正在运行的进程
手里会留下指向已删除文件的句柄。

可以用 `NODES_DATA_DIR` 把数据放到别处（例如同步盘）：

```bash
NODES_DATA_DIR=D:\我的笔记\nodes-data npm run dev
```

注意它指的是**数据目录本身**，程序会在其中创建 `nodes.db`。启动前确认该
目录已存在且可写。

## 已知限制

- **`next build` 在受限沙箱下无法完成。** 实测：编译阶段 4.9 秒成功
  （`next build --experimental-build-mode=compile` 也通过），失败点是
  "Collecting page data using 15 workers" —— Next 要 spawn 子进程收集页面
  数据，沙箱拒绝 `spawn`（EPERM）。webpack 打包器同样如此，所以不是
  Turbopack 的问题。`next dev` 与所有 API 路由正常。在普通环境下
  `npm run build` 应当正常。
  因此类型检查被移到独立的 `npm run typecheck`（覆盖范围比 Next 内置检查更全），
  提交前请跑 `npm run verify`。
- **没有真正的多用户。** `getWorkspace()` 永远返回第一个工作区，这是刻意的：
  先跑通单机体验。要加多用户需要引入认证与 workspace 归属校验。
- **历史不做摘要压缩。** 自动把长历史压缩成摘要会破坏 L3 的"只追加"性质、
  让缓存前缀每轮都变。当前实现选择保住命中率，代价是超长对话最终会撞上下文窗口
  （界面会提前告警）。若确实需要压缩，应当做成显式操作并在 UI 上标注代价。
- **知识块只按稳定顺序挂载，不按相关性挑选。** 相关性会随问题变化，
  那会让 L2 每轮都不同、缓存直接归零。超出预算时按稳定顺序截断，
  清单里仍会列出被截断的块，让模型知道它们存在。
- **没有块级向量检索。** 这是有意的取舍：检索结果每轮不同，与缓存命中直接冲突。
  需要检索时应当把结果"固化"成一次显式挂载，而不是每轮重新检索。
- 块级 diff 视图、文档树拖拽排序尚未实现（重命名已支持：树里双击文档名）。
