# 带回去怎么跑起来

## 一分钟跑起来

```powershell
# 1. 解压后进入目录
cd <解压出来的 nodes 目录>

# 2. 确认 Node 版本（需要 20 以上，22+ 更稳）
node -v

# 3. 启动
npm.cmd run dev
```

然后浏览器打开 <http://localhost:3210>。

**注意用 `npm.cmd` 而不是 `npm`**：Windows PowerShell 默认禁止执行 `npm.ps1`，
直接敲 `npm` 可能报"无法加载文件……因为在此系统上禁止运行脚本"。

如果宿舍机器上 `npm` 反而正常，用 `npm` 也行，两者等价。

## 第一次启动会慢

第一次打开页面要等十几秒到一分钟，因为 Next.js 要现场编译。终端里会刷
一堆 `✓ Compiled in xxxms`，**这不是错误**，是在编译。之后就快了。

页面第一次可能返回 500——多半是还没编译完，刷新一下即可。

**例外：压缩包里已经带了 `.next/` 缓存时不会慢。** 那时 `next dev` 会直接
打印 `✓ Ready in xxxms`，首屏一两秒就出来，属于正常现象，不是没编译。

## 防火墙提示

Windows 可能弹"是否允许 Node.js 通过防火墙"。**选取消或不允许都可以** ——
这个应用只在本机 `localhost` 上跑，不需要联网对外提供服务。
（它需要的是**访问外网**去调 AI 接口，那是出站方向，防火墙不会拦。）

## 你的数据在哪

全部在项目目录下的 **`.data/`** 里：

| 文件 | 内容 |
| --- | --- |
| `.data/nodes.db` | 所有文档、知识块、会话、模型配置（单文件 SQLite） |
| `.data/assets/` | 你上传的图片 |

**换机器、备份、或者想同步到网盘，复制这整个 `.data/` 目录就够了。**
不需要导出功能，也没有云端。

### 备份建议

关掉服务之后再复制 `.data/`，否则可能复制到一个正在写入的库。
（SQLite 能保证不损坏，但可能漏掉最后几条还没落盘的改动。）

## 两个压缩包的区别

| 包 | 体积 | 什么时候用 |
| --- | --- | --- |
| `nodes-full-*.zip` | 约 430 MB | **推荐**。`node_modules` 已装好，解压即用，不需要网络 |
| `nodes-slim-*.zip` | 约 5 MB | 只在你有网络、且想自己装依赖时用：解压后先跑 `npm.cmd install` |

`full` 包大是因为带了 `node_modules`（400 多 MB，几万个文件）。
解压会比较慢，请留出时间。

## 常用命令

```powershell
npm.cmd run dev          # 开发模式启动（就是上面那条）
npm.cmd run verify       # 类型检查 + 单元测试 + 集成测试（改完代码后跑）
npm.cmd run typecheck    # 只做类型检查
npm.cmd test             # 只跑单元测试
```

改代码之后建议跑一次 `npm.cmd run verify`。它同时检查三件事：
类型、单元测试、集成测试。全绿才说明没改坏东西。

> 如果跑 `verify` 时提示 `check:encoding` 失败、说某个文件有乱码，
> 那说明编辑时用了会破坏中文编码的工具（PowerShell 的 `Set-Content`
> 是元凶）。用 VS Code 之类的编辑器改就没事。详见 `AGENTS.md` 的 R1。

## 遇到问题

### 端口被占用

```
Error: listen EADDRINUSE: address already in use :::3210
```

改端口：`npm.cmd run dev -- -p 3211`，然后开 <http://localhost:3211>。
（注意是 `dev -- -p`，两个短横线。）

### 改了代码但页面没变

Next.js 会自动热重载。如果没生效，在终端按 `Ctrl+C` 停掉再重新
`npm.cmd run dev`。极少数情况下要删掉 `.next/` 缓存目录再启动。

### AI 回答是空的 / 报"输出被截断"

到「模型配置」里把这个模型的**最大输出 token** **留空**（= 不限制）。
思维链和正文**共用**这一个预算，填任何具体数字都可能被思考烧完。

对照着填：

```
上下文窗口       1000000        # 只用于界面占用条与"接近窗口"预警
最大输出 token   （留空）        # 留空 = 不限制，请求里不带 max_tokens
```

**为什么不是"填个大一点的数"**：留空时应用**根本不发** `max_tokens`，
由服务商按它自己的上限约束 —— DeepSeek 思考模式的原生默认是 64K。
而只要还填着数字，思维链够长就还能把它烧完：4096 烧完过一次，
提到 8192 之后**又烧完了一次**。留空是唯一不会撞上限的填法。

**两个字段的作用完全不同，别搞混：**

| 字段 | 到底干了什么 | 填错/填小了的后果 |
| --- | --- | --- |
| 上下文窗口 | **一个字都不发给服务商**。只决定右上角占用条的分母，和"输入超过 90% 就提醒你"的门槛 | 实际没超，却早早弹"已接近模型上下文窗口" |
| 最大输出 token | 真正发出去的 `max_tokens`；**留空则完全不发** | 回答被截断、正文空白 |

约束只有一条：**输入 + 输出要装得进上下文窗口**。所以窗口填得比真实值大
并不会报错，只是预警形同虚设；输出留空也不会失控 —— 模型写完了自然停。

> **Anthropic 是例外。** 它的 Messages API 把 `max_tokens` 定成**必填**，
> 省略不是"用默认值"而是直接 400。所以在 Anthropic 上"留空"会被兜成
> 64000 发出去，并且**每轮都会在对话里提示一句**这不是真的无上限。
> 用 Anthropic 就显式填一个它支持的上限。

### 模型配置怎么填（以 DeepSeek 为例）

```
接口类型         OpenAI 兼容
接口地址         https://api.deepseek.com          # 带不带 /v1 都行，实测两种都通
模型 ID          deepseek-flash
上下文窗口       1000000
最大输出 token   （留空 = 不限制）
```

两个容易踩的点：

- **模型 ID 必须填服务商认的接口名**，填产品名会被 400 拒掉。`deepseek-flash`
  就是接口名；反过来 `deepseek-chat` 是旧名字，现在由 flash 代跑并按 flash 计价。
- **思考模式下 `temperature` 无效**，DeepSeek 官方明确写了这一条 —— 那个温度
  滑杆对 deepseek-flash 是空操作，不用纠结填多少。

想省钱就在**额外参数**里关掉思考模式（思考 token 按输出计费，且和正文抢同一份预算）：

```json
{"thinking":{"type":"disabled"}}
```

### 喂不进长文档，不只是窗口的问题

容易误会的一点：**上下文窗口填 1M ≠ 你的笔记就会被塞进 1M。**
每轮真正展开的引用正文有个**独立预算 `source_budget_tokens`，默认 40000**；
超出预算的知识块**只把标题给模型看，正文不展开**，界面上会提醒
「有 N 个知识块因超出预算未展开正文」。

这个字段存在**数据库里（每个对话一份）**，目前**没有界面入口** —— 所以
"想让它一次读更多笔记"这件事，光调模型配置是办不到的。

### 数据库报 schema 相关错误

删掉 `.next/` 重新启动。**不要删 `.data/`** —— 那是你的笔记。

### 报 `Error: spawn EPERM`（启动就退出）

```
Error: spawn EPERM
    at ChildProcess.spawn (node:internal/child_process:440:11)
    at fork (node:child_process:174:10)
    at .../next/dist/cli/next-dev.js:303:45
```

`next dev` 必须 fork 一个子进程。**普通命令行里不会遇到这个**，
只有被沙箱/受限令牌限制 `CreateProcess` 时才会 —— 解决办法是放开限制再启动。

注意别和 `EADDRINUSE` 搞混：那个是端口被占（换个端口即可），
这个是进程根本没能创建起来（换端口没用）。

## 怎么确认这份包是好的

解压完先跑一次全量校验，再开服务：

```powershell
npm.cmd run verify
```

全绿（`check:encoding` 0 发现 + `tsc` 无输出 + 单元测试 + 集成测试）就说明
包是完整的、依赖也装对了。最近一次全量结果：**编码检查 56 个文件 0 发现、
类型检查通过、单元测试 236 项全过、集成测试 87 项全过**。

服务起来之后再跑一次冒烟，它会拿真实数据库走一遍主要接口
（建文档 → 建会话 → 跑一轮 SSE → 上传图片 → 清理）：

```powershell
node scripts/smoke.mjs
```

**冒烟测试只断言它自己创建的东西，跑完会清理**，所以在你已经有笔记的库上
反复跑也安全（见 `AGENTS.md` R10）。最近一次结果：**99 项全过，0 项失败**。
