# 网络同步的工程实现

> 状态：**大纲（未填内容）**。《状态同步机制》只有概念层，副标题承诺了「客户端预测、服务器和解、插值补偿」，正文没给 —— 这篇补的就是它。

## 1. tick rate / 快照 / 状态压缩

- 服务器 tick 多少、客户端多少
- 快照（snapshot）是什么，为什么不是每帧发全量

## 2. 插值（interpolation）与外插（extrapolation）

- 渲染帧和网络帧对不齐 → 角色抖动
- 延迟缓冲（buffer delay）换平滑
- 面试会问：「延迟 100ms 怎么让角色不飘？」

## 3. 客户端预测 + 服务器和解

- 为什么本地要立刻动（否则手感崩）
- 服务器纠正时怎么不「瞬移」（平滑拉扯 / rollback）
- 面试会问：「客户端预测后服务器说你是错的，怎么办？」

## 4. 延迟、抖动、丢包的处理

- RTT 与 jitter 的区别
- 丢包时 UDP 上的应用层重传策略

## 5. 帧同步的确定性（这一节最容易踩）

- 定点数、随机数种子、浮点陷阱
- 哪些 API 不能用（`Time.deltaTime`、`Random.value`、浮点运算顺序）
- 面试会问：「帧同步下能不能写 `if (Random.value > 0.5f)`？」
