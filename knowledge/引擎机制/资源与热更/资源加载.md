AB包同步/异步/协程、引用计数、Addressables
资源卸载链路：
● 底层：Resources.UnloadUnusedAssets() + GC.Collect()，清扫无引用残余
● 中层：ResourceManager.UnloadLevel(scene) 按场景批量卸，UnloadAssetBundle(name, count) 按单个 AB 包卸
● 上层：业务模块（ConfigMgr、MonsterTool）在读完配置或清理时主动调 UnloadAssetBundle
● 核心：参数 count 对应引用计数递减，计数归零才真正卸载
● 注意：协议里的 EquipUnload/UnloadData 是业务逻辑的“卸载装备/数据”，和内存管理无关
场景切换
  ↓
ResourceManager.LoadLevel(sceneName)
  ├── 读取场景配置，获取依赖的 AB 包列表
  ├── 遍历列表，逐个调用 LoadAssetBundle(abName)
  │     ├── 检查是否已加载过？
  │     │     ├── 已加载 → RefCount++
  │     │     └── 未加载 → 从磁盘/网络加载AB包 → RefCount = 1
  │     └── 返回 AB 包中的资源
  └── 场景加载完成
游戏运行中...
  ├── 怪物 ConfigMgr 加载配置表 → LoadAssetBundle("config.ab") → RefCount++
  ├── 怪物 ConfigMgr 读取完毕 → UnloadAssetBundle("config.ab", 1)
  │     └── RefCount-- → 如果 RefCount == 0 → 真正卸载 AB 包
  └── MonsterTool 清理 → 遍历 _controlDic，逐个 UnloadAssetBundle(key, 1)
场景切换离开
  ↓
ResourceManager.UnloadLevel(sceneName)
  ├── 遍历该场景加载过的所有 AB 包
  ├── 逐个 UnloadAssetBundle(abName, 1)
  │     └── RefCount-- → 如果 RefCount == 0 → 真正卸载
  └── 可选：调用 Resources.UnloadUnusedAssets() + GC.Collect()
        └── 清扫残余（没被任何引用但还没卸干净的对象）

同步加载：AssetBundle ab = AssetBundle.LoadFromFile(path);
GameObject prefab = ab.LoadAsset<GameObject>("Slime");
Instantiate(prefab);
异步加载：vary request = AssetBundle.LoadFromFile(path);
               request.completed += (op)=>{
                      AssetBundle ab = request.assetBundle;
                                                        }
协程+异步
IEnumerator LoadABAsync()
{
    var request = AssetBundle.LoadFromFileAsync(path);
    yield return request;  // 每帧检查 request.isDone，没完成就跳过
    // 到这里时加载已完成
    AssetBundle ab = request.assetBundle;
}
